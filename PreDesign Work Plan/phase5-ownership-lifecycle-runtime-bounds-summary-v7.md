# Phase 5: Ownership, Lifecycle and Runtime Bounds

## 1. Executive Outcome and Exact Readiness Boundary

**PASS at the accepted static pre-design boundary. READY FOR PHASE 6: Compare and Select a Proportionate Architecture.** EG1-EG6 are assessed independently in Section10. EG4 uses the explicit user-approved numeric-deferral clarification, not a claim that the original successful-support envelope has already been selected.

Capacity values may be selected after the HLD presentation and the architect's decision. They are not required to be chosen inside HLD. They must be finite, approved and prepared at Engine startup before the affected runtime path is enabled. No runtime allocation or growth is permitted. This deferral is explicit support-policy authority, not evidence that every value preserves identical successful traffic support. A value that requires changed ownership, unbounded work or a different mechanism reopens the affected design.

Completion policy is already accepted in Phase2-4: an unambiguously associated client QUIC v1 Handshake Long Header is product-level completion evidence, without Handshake payload decryption. Before authoritative CH it is bounded deferred evidence; after permitted CH/normal commit it can lead to Finished. Reclaim requires the eligible committed transition and last use. It is not observed TLS Finished.

This is the consolidated V7, not implementation, benchmark, interoperability, HLD or release certification. TCP corrections are adopted design obligations, not applied patches. Available source evidence, static proposed costs and planned validation are distinguished. V4 and earlier sources remain unchanged; review evidence and final digest are external. The ten required output sections follow without reproducing the earlier reports in full.

### 2.4 Binding Finished Policy Inherited from Phases 2-4

**ACCEPTED, not BLOCKED or a new proposal.** Authority: Phase 2 sections 5.1/5.2/6/9/11/12/13/16; Phase 3 transition coverage, OP-08, L11 and S6-05/19/20/21/23/32; Phase 4 D4-07, Q11/Q12 and D4-12. Phase 5 defines storage, lifetime and bounded execution for this policy; it does not require another completion decision.

- **TCP:** Preserve the existing completion predicates: a Handshake record in ChangeCipherSpec reaches Finished; TLS-1.3-offered ApplicationData reaches Finished only with committed CH count nonzero, InProgress and the existing !earlyDataOffered guard. These are existing heuristics, not decoded TLS Finished. Current-unit feedback can suppress normal commit.
- **QUIC after CH authority (EV15):** InProgress plus a qualified associated client QUIC v1 Handshake Long Header reaches Finished at the permitted normal commit. No Handshake payload decryption, endpoint confirmation, server traffic, TLS Finished or HANDSHAKE_DONE is required. The payload may be ACK-only or contain an unreadable encrypted close; neither possibility disqualifies header-based completion or establishes a readable alert.
- **Association:** Use the same DP Session transport tuple, consistent retained client SCID when nonzero, no retained-retired match and no ambiguity. Matching DCID is not required; zero-length SCID alone neither proves nor rejects association. The fixed bit alone is not a mandatory transition-validity condition. Version/form/type and packet bounds must be valid. Visible v1 Long Packet Type is distinct from protected PN length/number and Reserved bits; do not require unavailable Handshake keys to read the visible type, or interpret protected fields without the required recovery.
- **QUIC before CH authority (EV16):** Retain only bounded, qualified, same-attempt non-authoritative evidence and stay PreHandshake. When the first complete, parseable, non-retransmitted CH becomes authoritative through permitted normal commit, apply that retained evidence in the same semantic cycle: PreHandshake through InProgress to Finished. Partial, failed, suppressed, ambiguous or retired CH input cannot unlock completion. Candidate acquisition alone is not CH authority.
- **Feedback/commit:** R7 owns semantic commit; acquisition and parsers do not write hsState. The header-completion unit has zero consumer projections and neutral feedback, as Phase 4 Q11 specifies. Deferred completion is applied only if the first-CH transaction permits authority/normal commit. Zero-mask Stop may still permit that current-unit commit but ends later traversal; nonzero accumulated violations suppress normal commit, and combined Stop follows the existing Error disposition. Never process a later unit using pre-Finished permission.
- **Not completion:** CH alone without qualified current/deferred Handshake evidence leaves QUIC InProgress. 0-RTT, short-header 1-RTT, generic opaque payload, datagram exhaustion, aging, eviction and an Initial close are not substitute Finished triggers. Readable associated Initial CRYPTO_ERROR close follows TerminatedByAlert, not Finished. Required association/completion-state loss in InProgress follows Unsupported, not synthetic completion.
- **Reclaim:** Request reclaim eligibility only after a newly committed Finished transition and completion of current-unit last uses. Marking is not immediate release and does not prove successful marking. Preserve required terminal/late-input identity until its own valid lifecycle disposition. Repeated/late evidence cannot repeat the transition or mark. Deferred evidence alone before CH authority cannot mark. A new-attempt reset clears old deferred evidence and old reclaim membership; only accepted new-attempt classification can reopen terminal processing.

These rules apply consistently to INV-08, R001/R014/R052/R053, EV15/EV16/EV21/EV22, D6-07, B17, S6-06 and the Phase 6 handoff. The runtime remains startup-prepared and allocation-free; no new capacity value, callback, state, class or completion API is introduced.

### 3.2 Owner, scope, acquisition/mutation/read/release and validity

Physical backing belongs to the existing owning object chain prepared at startup. Logical owners claim/recycle it. No new Engine-global allocator service is selected. Release means recycle after last use; it cannot destroy/grow prepared backing during processing. Upstream input is borrowed only for its supplied call lifetime, never retained; its external concrete owner is not invented. External listeners own their targets, while Extension owns weak membership and a callback-local lock pins the target only.

### 5.0 Completion Association and Deferred Evidence

P2 Section9 requires the same DP Session transport tuple, matching retained client SCID when non-zero, no retained-retired classification and no ambiguity. Matching packet DCID is not required; zero-length client SCID neither proves nor rejects association. The fixed bit alone is not required transition-validity evidence. Read exposed v1 Long Header type/version/CIDs only; no protected PN or encrypted Handshake content is interpreted. A Handshake packet may be ACK-only or contain encrypted close: it remains product-level completion evidence, not a decoded alert.

Before CH, keep one bounded same-attempt progress fact; repeated evidence is idempotent. First authoritative CH may consume it only after required evaluation, callbacks/feedback and permitted normal commit. A terminal/violation/STOP gate that forbids normal commit also prevents deferred completion. Commit InProgress then Finished in that cycle; mark reclaim only once after producer last use. After CH, qualified evidence produces zero projections/neutral feedback and eligible Finished commit. Replacement never inherits deferred evidence; stale reclaim membership is removed before new lifecycle publication. Required evidence loss follows accepted-attempt Unsupported; optional retired-history loss does not fabricate completion or newness.

### 5.1 Adopted mechanisms and source compatibility

#### D6-01: Mode-Specific Current-Result Restoration

For TCP CH-extension reassembly only, neutralize CH-derived result flags/values (version mask/parsed flag, early-data offer, SNI flag/value/locator, current evaluation error/availability) before processing the complete retained extensions. Restore saved cipher/compression counts, own legacy version and digest/backing; recompute extension count/values from the same continuation. Use its saved legacy version for no-supported_versions fallback, not the shared parser. Do not hash prefix twice or reset saved digest. Rebind/copy final digest before freeing continuation. Packet-local record/error metadata must belong to the current invocation; full retransmission produces no new authoritative unit.

Do not indiscriminately reset OpaqueRecordTracking/AlertRecordReassembly or remove TCP U05 retained-Complete dispatch. They retain their source-preserved behavior; any field actually used as a fresh authoritative CH must have current provenance. QUIC complete-CH evaluation starts from neutral fields and its owned CH body, not TCP record/header state. This resolves the identified contamination dependency at design level; source implementation/tests remain required.

#### D6-02: Owned Acquisition, Rollback and Cleanup

Use a local acquisition ledger in the existing owner, not a new component. Track only successful acquisitions and ownership: new map entry, exact observer registration, candidate bytes/ranges, scratch, reservation and publication. A duplicate lookup is borrowed, not newly owned. Missing Session after successful insertion removes exactly the new unpublished entry. Check registration results and unwind only successfully installed registrations on partial failure. Construction failure must not publish participation.

No pointer/reference/iterator survives a potentially invalidating insert/pop/erase. Copy scalar cleanup keys and needed payload into owned stable backing before mutation; reacquire by key afterward. Invalidate Processor selectors before freeing their backing. Do not depend on undocumented CTUnorderedMap/FIFO reference stability. HLD may use existing containers only after verifying their relevant APIs; otherwise choose an owner-local implementation satisfying this contract without changing semantic outcomes.

Remove the exact owned observer registration outside its active traversal, using the verified identity/event/priority API; then erase owned support. During aging traversal, mark ownership retired and perform any required observer-list detach at the first safe serial boundary before index reuse; do not invent reentrant unregister behavior. No extra payload/replay queue is introduced. Repeated cleanup sees no owned resource and is a no-op. If detachment cannot be completed, do not publish reuse/destroy a still-registered owner: fail admission or keep the old binding alive until the safe boundary. An unexpected infrastructure invariant failure is not a client violation or automatic drop; it reopens integration rather than being misreported as successful cleanup.

Coordinate continuation and Extension cleanup for the same lifecycle before slot reuse. Terminal pressure reclaim clears any old support association before subsequent admission; it emits no SessionEnd. Registration/removal exception and return-value details remain explicit implementation verification gates. Static lifecycle reasoning does not assert that the old ignored-return/orphan branches are already fixed.

#### D6-03: Serial Live Interval

U6-02 guarantees no invalidating reentry or parallel processing during listener calls. Shared workspace remains bound through all callbacks, feedback and producer commit; reuse/reset/replacement/reclaim occurs only after last use. Listener shared_ptr pins the listener; owned backing plus this serial interval protects the borrowed TLSData/view. No borrowed viewer or TLSData reference may be retained after its documented synchronous use. Later lifecycle operations run serially; observer-list detach and index reuse obey D6-02. Shutdown stops new entry, ends current call, detaches registrations and releases owned resources before owner destruction.

No locks, recursive-entry guards or new generation machinery are needed for this runtime contract. Do not turn this user guarantee into an assertion about arbitrary external container APIs.

#### D6-04: Support Exhaustion Is Unsupported, Including PreHandshake

When a required resource/representation or explicit supported-domain limit prevents reliable evaluation of the accepted associated attempt, transition to Unsupported in PreHandshake or InProgress. Do not require proof that the whole unparsed input is valid: record the local support cause, not a fabricated peer violation. Clear current success availability before any same-unit consumer; no CH/count/time acceptance, no automatic drop, synthetic SessionEnd or Incomplete Handshake violation. Preserve prior authoritative facts and admitted minimal core/list binding while its retention obligation applies; release affected acquisition after last use.

A recoverable single-packet/trial failure is not automatically support exhaustion. A failed/unassociated candidate before acceptance is rejected locally, leaving old active state/backing unchanged. After terminal candidate acceptance, failure belongs to the new attempt and cannot resurrect old state. Same Unsupported attempt remains terminal; independently qualified new attempt can replace it under existing policy. No late fragment can silently reacquire discarded required state in the old attempt. Optional retired-history/key-cache eviction follows bounded missing-evidence/rederivation rules, not automatic Unsupported. Finished pressure reclaim and actual aging remain permitted separate boundaries.

This is an explicit user-authorized extension of the older P2 Section13 InProgress-focused required-loss rule; it is not an accidental claim that the older baseline already specified PreHandshake behavior.

#### D6-05: Finite Admission, Reservation and Peak

Select finite positive tunable capacities for core entries, bytes, spans, ranges, contexts, candidate backing and optional history, plus a finite Engine budget covering metadata/allocator overhead and temporary replacement peak. Admission checks all relevant dimensions before mutation. Reserve minimum semantic/list binding before publishing participation. Preserve old required backing until last use; reserve old+candidate peak before candidate acceptance. Failed new participation admission creates no half binding; if a supported classification cannot be bound, no consumer runs. Existing unrelated attempts are not poisoned by global capacity failure.

Exact numeric values are HLD/configuration choices, not silently promised support of every legal traffic pattern. Their semantic outcome is already D6-04. A profile requiring a different outcome or changing ownership reopens this review. Sparse offsets allocate only retained chunks/ranges, not holes. Required accepted identity/PN/delivery provenance cannot be silently evicted: take D6-04 before losing reliable association. Optional history is bounded and expires after last use; no indefinite suppression promise. Every loop advances input or finite retained-set progress, including zero-length CRYPTO/PADDING; finite range/context caps bound scans/trials per finite invocation. No arbitrary work-budget tail cutoff is selected. Unlimited lifetime input implies unlimited total work, not unbounded retained state. Throughput/fairness measurements are not certified here.

#### D6-06: Initial/PN Contract Consistent with SRS and RFC

Use the Section10.5 provider-independent ownership/failure contract. For v1 Initial, validate packet boundaries and sample containment; remove header protection before PN length/value interpretation; use correct retained Initial derivation input, private unprotected-header/AEAD scratch and current-context reference. Parse CRYPTO only after AEAD success. Initial AEAD success does not authenticate peer identity (RFC9001 Sections5/7).

The design uses the standard RFC9000 Section17.1/AppendixA.3 reconstruction: one candidate PN per eligible admitted context and appropriate retained Initial-space reference, initialized to expected zero when no successful observation exists. Never decrease largest-successful reference on reordered packets; do not reset it merely because Retry-compatible keys/context change (RFC9000 Section17.2.5.3 prohibits PN reset on Retry). Context-specific hypothesis/reference bookkeeping is not a second wire PN space. A later DCID change does not automatically change Initial keys (RFC9001 Section5.2). No arbitrary CID/PN brute force, server visibility or later-level keys are assumed.

This is a design choice derived from the SRS scope and standard decoder, not an explicit user quote approving a universal late-capture profile. The SRS requires fragmented/multipacket CH support within the implementation domain; it does not guarantee decryptability with arbitrarily missing PN history. A failed trial alone gives no violation/newness/Unsupported inference. If a known required PN-reference/support limit prevents continued reliable inspection of an associated accepted attempt, D6-04 applies. Unknown unassociated decryption failure is local and cannot mutate old active authority. Independently processable later coalesced packets remain eligible unless existing STOP or accepted Unsupported scope prohibits delivery.

For v1 long headers, type bits are unprotected; classify Initial using validated version-aware header form/fixed/type fields, not first-byte equality to 0xC0. Reserved/PN-length bits and PN remain protected. The supplied SRS's 0xC0 is interpreted as the Initial high-bit pattern, not a restriction excluding other protected low-nibble values. CRYPTO type0x06 and handshake type0x01 are checked after decryption and logical reassembly, not by scanning ciphertext. Logical CH freshness/delivery provenance suppresses retransmitted data even when packet PN/datagram layout differs. Shared fingerprint algorithm/statistics and no reporting change are preserved. Mitigation construction/consumer actions remain outside this lifecycle closure and are not added to Processor.

#### D6-07: Dispatch, STOP and Completion Authority

Required current-unit evaluation precedes every consumer call; explicit Unsupported means zero same-unit consumers, even if anomaly is independently available. Preserve actual feedback reducer: zero-mask Stop halts that listener list but permits existing remaining current-unit projections/normal commit; later traversal stops. Accumulated violation plus latched Stop commits Error under the existing contract. Backing survives permitted callbacks/feedback/commit.

Deferred pre-CH evidence is nonauthoritative and cannot mark reclaim. P2 Sections5.2/6/9 and P4 Q11 already authorize associated client v1 Handshake-header completion: after same-attempt authoritative CH and permitted commit, Finished becomes eligible for reclaim after last use. Repeated evidence does not create a new transition/mark. Scenario6 checks this ordering, not endpoint TLS Finished visibility.

## 6. Bound Register and Bounded-Work/Storage Model

### 6.1 Overflow-safe enforcement

Every register row uses these rules as applicable. Checks occur before expensive work or allocation, not after damage. Arithmetic rejection is not automatically a client violation.

- **G1 count/size admission:** validate current<=cap, then delta<=cap-current before increment. Distinguish current occupancy from high-water/cumulative work. Never wrap, truncate or saturate to make admission appear successful.
- **G2 extents/offsets:** validate start<=limit and length<=limit-start before computing end; verify encoded length fits current packet/frame remaining and representable host size before narrowing. CRYPTO end additionally<=2^62-1. Header sample must fit current packet, not remaining datagram. For multiply/stride, check count<=remaining/element_size first; no signed pointer arithmetic on unvalidated bounds.
- **G3 memory reservations:** account payload, metadata, fixed backing, alignment/allocator overhead and temporary overlap. Checked sum/product; reserve engine budget before allocator/provider call. Publish coverage/binding only after all currently required ownership succeeds. Release reservations exactly once at last use; bytes freed from one owner are not freed again by another.
- **G4 work charging:** account each visit/trial/compare/copy/derivation including failures/duplicates in the static work model. Include input parse, pending-message unlock and cleanup. This does not require a runtime work counter, token mechanism or cutoff. If a work-admission mechanism is later proposed, validate its envelope before operation and resolve section8.7 before adoption; accounting alone never authorizes tail skipping.
- **G5 time/lifecycle:** use verified monotonic/wrap-aware elapsed time; qualify lifecycle before expiry. No equality of recycled session index proves same lifecycle. Numeric clock/counter overflow policy is not invented.

Current G3: prepare physical backing at startup; runtime reservations claim existing capacity, never call an allocator. Check each class and joint peak before publication/acceptance. No platform budget is invented. G4 is accounting/progress reasoning, not a mandatory work counter/cutoff.

### 6.3 Aggregate and replacement storage/work model

M_prepared is the sum of actual startup-backed core/table/list/registry, TCP continuation, QUIC byte chunks, range/message descriptors, Initial context/reference/identity, candidate staging, evaluator/plaintext/provider scratch, any separate transfer destination, and index/free-slot/alignment/control overhead. Idle prepared slots remain resident. Do not multiply logical occupancy by sizeof and call it total reserved memory if the whole container is prepared. No numeric physical bound is claimed until actual layout/all backing is covered; finite layout obligations are explicit.

For each prepared class j, simultaneous claimed usage must not exceed its fixed capacity. Old live backing is not freed to fund an unaccepted candidate. Stable transfer can avoid a destination only if references remain valid; otherwise count prepared destination+source until rebase completes. Required minimal core/list binding is claimed before publication/irreversible reset and remains until permitted release/reclaim after last use.

Invocation work includes validated packet/frame/nested traversal; scoped identity scans; finite range search/merge and actual compared bytes; newly unlocked messages including retained data; CH parse/sort/hash passes; all cold derivations/HP/AEAD failed and successful trials; copied/rebased bytes; callback/reducer/commit; victim cleanup and affected diagnostics. Runtime heap-allocation term is zero by required design, not measured zero in supplied code. Slot claim/recycle and copies still cost work. Each loop advances validated input, a bounded iterator or finite pending progress, or terminates. Context trials are at most the admitted eligible set, one reconstructed PN each; no brute force or voluntary tail cutoff. Lifetime CPU under unlimited arrivals is not bounded by this model.

For each prepared class, active plus candidate plus old-still-live plus separate destination must fit its startup capacity before acceptance. Count old storage once if already included in active. Count byte slack, descriptor/index/free-slot/control/alignment and provider backing, including idle capacity. Fixed resident backing is not occupancy multiplied by payload size. A physical numerical upper bound requires actual layout and all backing terms; no target-fit claim is made.

Work envelope: packet/frame/nested visits follow validated input progress; interval scans/shifts are bounded by admitted descriptors; overlap cost counts repeated compared bytes; pending-message unlock includes retained bytes; CH parse/sort/hash counts actual passes and compared values; eligible context set bounds one reconstructed PN/trial per context; failed/cold derivations/HP/AEAD/copies/callbacks/cleanup/inspection all count. Finite per-call work is not constant time, lifetime CPU, throughput or fairness. H8.5-8.6 retain the detailed M1-M3/W1-W6 derivations; this summary does not repeat them or claim their unknown coefficients measured.

### 6.3.1 Explicit Symbolic Dependencies

For each physical prepared storage class j, C_j is its startup capacity in slots, s_j is the charged bytes per slot including inline metadata, and O_j is class-level index/free-slot/alignment/control overhead. F is fixed Engine-local evaluator/plaintext/provider backing not already charged to a class. Then **M_prepared = F + sum_j(C_j * s_j + O_j)**. Variable-sized byte backing is a byte-slot class; do not charge it again inside a descriptor. The chosen layout determines s_j/O_j/F; these are unmeasured layout terms, not selected values or a platform-fit proof.

For each class, A_j is active usage including any still-live old attempt, K_j is isolated candidate usage, D_j is a separate destination and T_j is other concurrent temporary claims. Admission requires **A_j + K_j + D_j + T_j <= C_j** with checked arithmetic before mutation/publication. If old usage is included in A_j, do not add it twice. This captures the replacement peak independently of serial execution.

Per invocation, P is packets visited, F_r is frames/nested visits, N is unlocked logical messages, V is retained range/identity entries visited, X is overlap bytes compared, Y is bytes copied/rebased, H is CH bytes parsed/hashed, Z is locator/sort comparison work, T is eligible context trials, K_d is key derivations, and L is cleanup/aging/inspection entries processed. C_b is consumer callbacks. Each is limited by validated input progress or the admitted finite retained sets and bound-register dependencies; N/H may include bytes retained before this input. One reconstructed PN per eligible context bounds T; no brute force is selected.

A work model is **W = aP + bF_r + cN + dV + eX + fY + gH + hZ + W_crypto(T,K_d) + W_callbacks(C_b) + W_lifecycle(L)**. Coefficients and crypto/callback/lifecycle service costs are unmeasured; the ledger and V7 obligations define how to validate them. Range shifts/merge scans contribute to V/Y; repeated retransmissions contribute to X/T/K_d even without a new callback. Aging/cleanup are Engine runtime work, not free background activity. This model states explicit dependencies, not a numerical time bound, rate guarantee or proof from finite input size alone.

### 6.4 Work-tail and unit boundary

No arbitrary early cutoff is selected. STOP ends later delivery at its accepted boundary; zero-mask current-unit projections/commit remain as specified. Unaccepted candidate failure does not terminalize unrelated active units. Accepted required-loss Unsupported is decided before same-unit callbacks and preserves earlier committed units; later independent candidates require terminal/association gates. No tail queue/replay/global Unsupported/drop is invented. Any future cutoff needs a support-policy decision or proof it cannot omit supported observations.

#### Phase 6: Compare and Select a Proportionate Architecture

##### Work

Compare at least four concise, genuinely different candidates:

This is a required investigation, not a predetermined refactoring decision. Identify which transition logic can move unchanged, which requires generalization, and which should remain protocol-specific, with justification based on semantics, regression risk, and delivery cost.

Candidate 4 is mandatory to evaluate, not mandatory to select. Its logical layers do not each require a new class. Shared state policy does not require a full TLS endpoint, uniform observability, or buffering complete TCP handshake messages when staged evaluation can preserve behavior.

For each candidate, explicitly compare how much TLS semantic processing and state policy is shared, what remains protocol-specific, and why. Evaluate both benefit and current delivery cost.
